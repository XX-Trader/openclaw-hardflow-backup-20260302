# 外部学习闭环与 5 台服务器部署计划

## 1. 目标

本次工作分两部分：

1. 把“如何让工作流持续从网络上学习其他人的 agent / skill / workflow / prompt，并安全吸收”为一条受管闭环，明确当前缺口与下一步事项。
2. 将当前 workflow runtime 重新部署到 5 台 OpenClaw 服务器：
   - `pm-website`
   - `大白pm`
   - `nofx`
   - `coingod`
   - `tokyo-claw`

明确排除：

- `google-us`
- `hangqing-zhongxin`

## 2. 当前判断

当前仓库已经具备以下能力：

- `github_web_evolution_runner.py`：可搜索 GitHub repo，并可选接入 `skill4agent` 搜索技能目录。
- `web_intel_collect_runner.py`：可抓取官网/文档类网页，并在失败时派生修复任务。
- `web_intel_review_runner.py`：可对采集结果做结构化复核，并派生 follow-up task。
- `governance_evolution_runner.py`：可把治理类增量变化打包为优化任务，且在满足条件时可选自动 push / PR。
- `git_sync_push_runner.py`：可对受控仓库执行 `fetch / pull --ff-only / commit / push`，并带远程 URL 白名单。
- `reviewer_cron_runner.py`：已有基础安全审查能力，可扫描 secret、`eval/exec`、`shell=True`、`verify=False`、危险 JS 执行等风险。

当前缺口同样明确：

1. 发现层已经有了，但“模式资产化层”还没有真正实现。
2. `PatternCard / pattern_extractor / pattern_sandbox_eval / pattern_promotion_gate` 仍停留在文档方案，没有工程落地。
3. 现有 GitHub/Web 搜索仍偏 OpenClaw 自身，尚未系统化搜索外部高质量 `AGENTS.md / SKILL.md / HOOK.md / CLAUDE.md / eval / guardrail / handoff` 资产。
4. 外部学习链路尚未形成完整的 `发现 -> 抽取 -> 评估 -> 晋升 -> 落地 -> 回归验证` 闭环。
5. 当前多台 runtime 机器上的相关任务曾出现停滞或报错，部署后必须重新验收。

## 3. 需要做的事情

### 3.1 发现层扩展

1. 扩展 `github_web_evolution_runner.py` 的 query pack：
   - 增加 `AGENTS.md`
   - 增加 `SKILL.md`
   - 增加 `HOOK.md`
   - 增加 `CLAUDE.md`
   - 增加 `guardrail / handoff / eval / agent team / workflow runtime`
2. 把“官方方法源”和“社区可执行资产”分层存储，不再把它们混在同一批变化项里。
3. 为外部学习单独输出 source tier 字段：
   - `official`
   - `community-executable`
   - `curated-index`
   - `weak-signal`

### 3.2 资产化层补齐

1. 落地 `PatternCard` 作为唯一中间对象。
2. 新增 `pattern_extractor.py`，把外部发现结果转成结构化卡片。
3. 新增 `pattern_sandbox_eval.py`，对候选模式做受限验证。
4. 新增 `pattern_promotion_gate.py`，决定是：
   - 仅归档
   - 进入沙箱
   - 生成 draft skill / agent / workflow
   - 派发人工审查任务

### 3.3 安全与治理补齐

1. 对外部资产新增 license / usage note 检查。
2. 对外部资产新增权限边界登记：
   - 是否要求 shell
   - 是否要求浏览器
   - 是否要求网络写操作
   - 是否要求 git push / PR
3. 对外部资产新增 benchmark / rollback 要求。
4. 未经 gate 审核的外部 prompt / skill 不得直接进生产 workflow。

### 3.4 运行恢复与验证

1. 修复目标服务器上的 runtime 依赖问题：
   - `scrapling`
   - Playwright 浏览器可执行文件
   - OpenClaw gateway 存活状态
2. 重跑 workflow 安装器。
3. 抽样验证：
   - hook 加载
   - cron 安装
   - task executor
   - web-intel collect/review
   - github evolution

## 5. 本次部署步骤

### Step 1: 远端仓库巡检

目标：确认 5 台服务器上的 workflow 仓库路径、分支、ahead/behind、dirty 状态是否可安全同步。

建议命令：

```bash
python scripts/openclaw-ops/remote_safe_update.py --mode inspect --servers pm-website 大白pm nofx coingod tokyo-claw
```

### Step 2: 远端仓库同步

目标：将 5 台服务器上的 workflow repo 拉到最新受控状态。

建议命令：

```bash
python scripts/openclaw-ops/remote_safe_update.py --mode sync --strategy runtime-reset --servers pm-website 大白pm nofx coingod tokyo-claw
```

如果发现非运行态改动阻塞，再改用：

```bash
python scripts/openclaw-ops/remote_safe_update.py --mode sync --strategy stash-nonvolatile --servers pm-website 大白pm nofx coingod tokyo-claw
```

### Step 3: 重跑 workflow 安装器

目标：在每台目标机上重装当前 workflow profile，并刷新 hooks / cron / runtime bridge。

远端执行：

```bash
python3 ~/.openclaw/ops/install_workflow_profile.py --profile core --workflow-repo-path ~/openclaw-hardflow-backup-20260302 --emit-json
```

### Step 4: 远端验收

每台服务器至少检查：

```bash
openclaw hooks check --json
openclaw hooks list --json
openclaw agents list
python3 ~/.openclaw/ops/ensure_runtime_skills.py --dry-run --emit-json
python3 ~/.openclaw/ops/bootstrap_runtime_agents.py --dry-run
```

如果要确认官方 cron surface，可补：

```bash
openclaw gateway run
```
