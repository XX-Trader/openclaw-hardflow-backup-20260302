## 需求背景与问题定义
开发者日常会在本机不同的 IDE 或终端使用各类 AI 助手辅助编码（包括 Claude Code, Antigravity, Gemini, OpenClaw, Codex CLI）。这些助手的历史问答、上下文逻辑散落在不同的本地临时目录和数据库中。
**此特性旨在构建一个跨平台的收集引擎，能够跨端抓取这些异构日志流，转换为标准化结构后送入下游的自动进化/蒸馏流程（如 MemTidy 机制），从而防重漏并且提取高价值的“编码经验沉淀”。**

## 验收标准 / 功能边界
1. **自动嗅探与抓取**：扫描并读取以上各 AI 助手的本地运行数据存储区。
2. **异构转同质**：将各类零散的 SQLite/JSON/Markdown 转译为统一的 OpenClaw Session 格式。
3. **安全闭环**：只在本地进行提取和转存，不上传远端；对接现有的 `optimization-agent` 闭环。

## 安全与边缘情况警戒线 (Security & Edge Cases)
1. **防凭证泄露脱敏 (Secrets Redaction)**：IDE 聊天日志中极有可能会误含生产密钥、API Keys 等敏感数据，**严禁在静态清洗期将未经本地安全正则扫描的原生数据直接发往云端大模型做蒸馏**以防密文飞出外网。
- **直连只读挂载 (Read-Only Direct Mount)**：为避免大规模全量冷拷贝产生冗余的大量 I/O 卡顿消耗。探针对文件和数据库抛弃冷备拷贝，强制直接原生挂载模式。处理 SQLite 务必使用 `?mode=ro` 只读标识连接，普通文本强行 `r` 模式读取。实现低消耗且零死锁。
- **经验血统可溯源 (Knowledge Traceability)**：AI在提炼的过程中有极大概率产生“幻觉合并”。当应用在生产的防坑红线被证伪时需要排错。要求蒸馏生成的每条新知识，必须在末尾打上防伪来源属性（例如 `Origin: ClaudeCode::[Session_ID]`）。

## 5. 端到端 (E2E) 执行流水线流转
在完成所有基础设施开发后，一次跨端捕获蒸馏会走过以下 6 个沙盘生命周期：
1. **触发与直连 (Phase 1: Trigger & Mount)**：Cron / jobs_agent 深夜触发，Python 探针通过纯只读句柄，直连各底层的 IDE 本机库数据映射。
2. **游标寻址与切块 (Phase 2: Cursor & Chunk)**：比对 `.sync_cursor` 丢弃已蒸馏过的冗余信息。取出新段落，依据硬分段切片（防止超过 Token 上限）。
3. **静态清洗与降噪 (Phase 3: Clean & Mask)**：脱敏工具本地正则抹除密码、Bearer Token。并剔除无用的系统自带 Prompt 填充和纯执行失败记录。
4. **多维萃取 (Phase 4: Matrix Distillation)**：挂载 `Analyzer Prompt` 分发给大模型（Distillation-Agent）。按照前端/后端角色，抽取拆分 L2 事实、L3 经验、L4 技能建议、偏好红线。
5. **仲裁碰撞 (Phase 5: Merger & Arbitrator)**：将提取物与主干项目已落盘的记忆库比较（增量补充/同义合并）。发现互斥与翻转的，挂起流程输出到 CLI 等待第二天的用户手动裁决。
6. **落盘拔营 (Phase 6: Commit & Advance)**：用户裁定后/或无冲突时，合并覆写进 OpenClaw 五层体系源文件，最后推进更新各途径对应的 `.sync_cursor` 指针，销毁临时冷备。
