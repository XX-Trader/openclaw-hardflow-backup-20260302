## 一、审计背景

参照两个外部项目提炼优化思路：

- **[AutoResearchClaw](https://github.com/aiming-lab/AutoResearchClaw)**：23 阶段全自动科研流水线，核心亮点为 MetaClaw 跨次学习（失败→Lesson→SKILL.md→注入后续所有阶段）、`ITERATIVE_REFINE` 自愈阶段、反幻觉校验系统

## 三、发现的问题

### 🔴 P0 — 阻断项

#### 1. `score-policy.json` 缺少 `refine` gate

已注入的 `iterative_refine` 阶段引用了 `"score_gate": "refine"`，但 `score-policy.json` 中**没有该 gate 定义**。hardflow 引擎在该阶段会无法正常评分。

**修复**：在 `score-policy.json` 的 `gates` 中添加 `refine` gate。

#### 2. `algo_micro_optimizer.py` 物理脚本不存在

`cron/jobs.json` 中已注入的 5 分钟高频沙盒任务调用了 `algo_micro_optimizer.py`，但该脚本尚未编写。每 5 分钟必触发 `FileNotFoundError`。

**修复**：编写该脚本。前置条件——需确认"评估指标"（策略回测收益率？信号准确率？测试通过率？）。

#### 3. TODO.md P0 部署任务未完成

- 5 台服务器环境配置未补齐
- 正式 `project-registry.json` 未在其他服务器落地
- `coding-default` 的 manifest/安装入口未正式化
- 任务层缺少 `workflow_profile_id` 与 `required_capabilities`

### 🟡 P1 — 高杠杆改进

#### 4. 进化闭环严重残缺

10 个进化相关 Job 中有 7 个处于禁用状态。进化链断裂：治理巡检能发现问题，但无人执行修复、无人评估结果、无仪表盘可视化。

**修复**（分两批启用）：

| 第一批（立即） | 理由 |
|---|---|
| `optimize 自我进化总结` | 进化链的核心反馈信号 |
| `upgrade_feedback_daily` | Workflow scorecard 量化指标 |

| 第二批（观察 1 周后） | 理由 |
|---|---|
| `benchmark_sweep_12h` | 客观质量基线 |
| `optimize 治理巡检` | 高频问题发现 |
| `control_plane_optimization_advisor_12h` | 自动派发优化任务 |
| `control_plane_summary_daily` | 控制面可视化 |
| `control_plane_dashboard_daily` | 看板快照 |

#### 5. `role_only` Agent 无 Skill 绑定

`optimization-agent`、`ops-agent`、`project-agent` 等 5 个 Agent 的 `declared_skills` 为空。在 `iterative_refine` 等需要特定 skill 的阶段会导致能力缺失。

**修复**：至少为 `optimization-agent` 声明 `systematic-debugging`、`auto-fix`；为 `ops-agent` 声明 `deployment-test`、`openclaw-security-audit`。

#### 6. 缺少跨次学习机制（MetaClaw 模式）

当前系统修完 Bug 后经验即丢失，下次遇同类问题仍从零排查。

**修复**：编写 `lesson_to_skill.py`，在 `iterative_refine` 阶段修复成功后自动提炼经验为 `SKILL.md`，存入 `~/.openclaw/skills/auto-learned/`，后续工作流自动加载。

### 🟢 P2 — 降低复杂度

#### 7. `candidate` 通道从未使用

数据库查询证实 0 条记录走过 candidate 通道。4 个 profile × candidate = 4 个死配置块。

**修复**：删除所有 `"channel": "candidate"` 配置块，配置文件体积减半。

#### 8. `policy_enforcer.py` 是 270KB 巨型单体

**修复**：按职责拆分为策略执行、任务路由、评分计算等独立模块。

### 🔵 P3 — 后续演进

#### 9. 为 `ops-default` 工作流注入 `iterative_refine`

运维任务涉及脚本和配置变更，同样适合自愈重试。

#### 10. Registry 配置 JSON Schema 强校验

非法配置直接 fail-fast，防止运行时静默失败。

#### 11. 高危操作审计日志

所有配置变更、任务删除、权限调整记录可溯源日志。

## 五、执行路线图

```
Week 1（消除阻断）
├── 补 refine gate 到 score-policy.json
├── 确认评估指标 → 写 algo_micro_optimizer.py
└── 执行 openclaw reload

Week 2（补闭环）
├── 启用进化 Jobs（第一批）
├── 补 role_only Agent 的 Skill 绑定
```
