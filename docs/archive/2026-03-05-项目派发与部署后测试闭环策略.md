# 项目派发与部署后测试闭环策略（2026-03-05）

## 目标
- 项目类任务由 `project-agent` 做上下文与规划，不直接写业务代码。
- 一旦识别为“编码类任务”，必须派发到执行代理（`backend-dev` / `frontend-dev` / `tester`）。
- 部署成功后必须执行 `post-test`，失败则进入“修复 -> 再测”闭环，不允许直接判定任务通过。
- 所有 agent 默认输出中文（简体，`zh-CN`，用户可显式覆盖）。

## 已落地策略
- `scripts/openclaw-ops/policy/policy-config.json`
  - 新增 `project_dispatch_policy`
  - 新增 `post_deploy_test_policy`
  - 新增 `agent_output_policy`
- `skills/library/control-plane-ops/scripts/policy/policy_enforcer.py`
  - `route-task`：当任务命中编码关键词且原始归属为 `project-agent` 时，强制改派执行代理。
  - `report-agent-result` 状态同步：若检测到 `deploy` 成功但缺失 `post-test`，任务保持 `running` 并设置 `action=post_deploy_test_required`。
  - 若 `post-test` 失败，任务转 `failed`（或达到阈值后 `escalated`），并设置 `action=retry_fix_after_post_deploy_test`。
- `skills/library/todo-patrol/scripts/todo_patrol.py`
  - 新增编码任务关键词分流，避免“项目 + 编码”任务继续落到 `project-agent`。
  - 任务上下文补充默认语言策略标记 `output_language_policy`。

## 验证命令
```bash
python3 skills/library/control-plane-ops/scripts/policy/policy_enforcer.py route-task \
  --description "项目重构并修复 API bug，写代码后部署并回归测试" \
  --source ops --request-source human

python3 skills/library/control-plane-ops/scripts/policy/policy_enforcer.py task-report \
  --task-id <task_id>
```
