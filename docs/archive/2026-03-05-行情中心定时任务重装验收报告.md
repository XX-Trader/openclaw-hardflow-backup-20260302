## 6. 故障根因与修复

### 6.1 project-index 持续失败根因

数据库中存在失败记录（`agent_task_reports`）：

- 错误：`git pull failed`
- 关键原因：`untracked working tree files would be overwritten by merge`
- 具体冲突路径：`.workflow/project-index/*`

即：运行态索引文件落在了会被远端跟踪更新的目录，导致 `pull --ff-only` 冲突。

### 6.2 push 失败风险根因

`git_sync_push_runner.py` 旧逻辑在“本地分支落后”时，只要检测到任何本地变更（包括排除目录下未跟踪运行态文件）就直接报：

- `behind_with_local_changes_requires_manual_rebase`

这会把可自动处理的场景误判为阻塞，导致同步/推送链路卡住。

### 6.3 已落地修复

1. `scripts/openclaw-ops/git_sync_push_runner.py`
   - 新增 `.workflow/project-index-local/` 默认排除。
   - 新增 pull 前变更分类：只把“真正阻塞 pull 的改动”作为阻塞项。
   - 排除目录下的未跟踪运行态文件不再误判为必须人工 rebase。

2. `scripts/openclaw-ops/cron_setup.py`
   - git-sync 默认排除前缀补充 `.workflow/project-index-local/`。

3. `scripts/openclaw-ops/policy/project_index_maintainer.py`
   - 默认索引目录改为 `.workflow/project-index-local`。
   - 当检测到 legacy 索引目录被仓库跟踪时，自动切换到 local 索引目录。

4. `scripts/openclaw-ops/policy/project_registry_runtime.py`
5. `scripts/openclaw-ops/policy/workflow_setup.py`
6. `scripts/openclaw-ops/policy/bootstrap_multi_project.py`
7. `scripts/openclaw-ops/policy/project-registry.example.json`
   - 默认 `index_dir` 统一到 `.workflow/project-index-local`。

附加验证：已在远端构造“分支落后 + 仅排除目录未跟踪文件”场景，`git_sync_push_runner` 可自动 `pull` 成功，`error_count=0`。
