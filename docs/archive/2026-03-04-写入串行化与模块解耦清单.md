# 写入串行化与模块解耦清单

更新时间: 2026-03-04（北京时间）

## 1. 目标与验收标准

- 目标 1: 文件写入不竞争，按顺序执行。
- 目标 2: 写入前有完整检查链路（目录缺失、权限不足、路径越界、磁盘异常）。
- 目标 3: 模块边界清晰，模块之间通过标准接口通信，不直接耦合内部实现。

验收标准:

- 同一路径并发写入不会互相覆盖或产生半写文件。
- 任意写入失败都能给出明确错误原因（如 `missing_parent_dir`、`permission_denied`）。
- 模块间只通过 `task_center + policy_enforcer CLI/JSON` 交互，不直接跨模块改文件。

## 3. 模块去耦边界（必须遵守）

### 3.1 统一交互契约

- 写任务状态: 只走 `policy_enforcer.py` 命令层，不允许模块直接改 DB 表。
- 写业务文件: 只走统一 `io_write_gateway`，不允许模块各自 `write_text`。
- 读统计数据: 只读 `task_center` 的标准视图/报表，不直接拼接其他模块内部文件。

### 3.2 依赖方向

- `入口/调度模块` -> `策略门禁模块` -> `任务中心模块`
- `执行模块（各 agent）` -> `回报模块` -> `统计模块`
- `运维巡检模块` -> `事件交接模块` -> `任务中心模块`

禁止反向依赖:

- 统计模块反向调用调度模块
- 执行模块直接改路由规则文件
- 任意模块跨边界直接写对方工作目录

## 4. 文件写入串行化流程（写入环节）

所有写入统一走以下 9 步：

1. `输入校验`: 目标路径、写入类型（覆盖/追加/原子替换）、权限级别。
2. `路径归一化`: 解析绝对路径，校验必须在允许目录白名单内。
3. `目录检查`: 父目录不存在则创建；创建失败立即返回 `missing_parent_dir`。
4. `权限检查`: 检查目录可写、文件可写；不足返回 `permission_denied`。
5. `串行锁`: 获取“按目标文件粒度”的 lock（同一文件同一时刻只允许一个写者）。
6. `临时写`: 写入 `*.tmp`，并 `flush + fsync`，禁止直接覆盖目标文件。
7. `原子替换`: `os.replace(tmp, target)`，避免半写状态。
8. `权限落盘`: 按策略 `chmod`（Linux 生效；Windows 兼容降级处理）。
9. `审计记录`: 统一写入 JSONL 审计日志（成功/失败、耗时、错误码、文件路径）；后续可选同步到 task_center 的 module_log。

当前审计实现:

- 默认文件: `scripts/openclaw-ops/policy/runtime/file_write_audit.jsonl`
- 环境变量覆盖: `OPENCLAW_FILE_WRITE_AUDIT=/abs/path/to/audit.jsonl`
- 环境变量关闭: `OPENCLAW_FILE_WRITE_AUDIT_DISABLED=1`

## 5. 文件权限策略（建议）

按数据敏感度分级：

- `secret`（token/key/auth）:
  - 目录: `700`
  - 文件: `600`
- `runtime`（状态、checkpoint、db 旁路 JSON）:
  - 目录: `750`
  - 文件: `640`
- `report`（日报、汇总、可共享报告）:
  - 目录: `755`
  - 文件: `644`
- `script/executable`:
  - 文件: `750`（仅可执行脚本）

## 6. 当前风险点（你关心的“竞争写入”）

当前代码中大量直接 `write_text`（尤其 `ops_cron_runner.py` 的 `save_json`、TODO 追加），风险是：

- 并发进程写同一文件时可能覆盖。
- 目录存在与权限检查不统一，报错点分散。
- 写入失败时缺少统一错误码和审计字段，排障成本高。

---

## 7. 落地顺序（最小可行）

1. 新增统一写入网关 `io_write_gateway.py`（锁 + 原子写 + 权限 + 审计）并接入。
2. 先替换高风险入口：
   - `skills/library/control-plane-ops/scripts/ops_cron_runner.py` 的 `save_json` 和 TODO 写入。
   - `skills/library/control-plane-ops/scripts/policy/policy_enforcer.py` 的配置/报表输出写入。
3. 再批量替换其它 `write_text` 脚本。
4. 最后加并发压测：2~4 个进程并发写同一状态文件，验证无覆盖、无半写、可追踪。
