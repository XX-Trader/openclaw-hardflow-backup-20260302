# 2026-03-04 项目规划对照与优化建议

## 1. 你的规划目标（原始诉求整理）

1. 运维 agent 定期把到时间的 TODO 发给规划者执行。
2. 日志巡检：识别问题与未解决项，避免重复报警。
3. project-agent 定期同步项目 Git，并做索引。
4. optimization-agent 读取本地 openclaw 配置/Git 更新，持续优化目标仓库。
5. optimization-agent 全量复盘对话记录与 memory，提炼经验，沉淀多层记忆。
6. optimization-agent 从互联网寻找可用进化技能，反哺仓库优化。
7. 每日工作总结（TODO/DONE）并发送钉钉消息。
8. 规划者（coordinator）负责分配任务给 agent/人类，收集结果并持久化；未分配任务可自执行并优化路由。
9. hooks 闭环：前后端完成后测试，失败回流重试（>3 转人工），成功则 push/review/deploy。
10. 每个 agent 有积分；任务成功得分。
11. 统计脚本覆盖 token、风险等级、复杂度、耗时、前后端、测试等评分。
12. 需求判断分流：清晰需求直达规划者，不清晰先 project-agent 澄清；人类需求反复核对，AI 需求可直派。
13. 群聊展示要体现完整任务环节与流转状态。
14. A2A 通信标准化：结构化输出、可溯源日志、携带完整上下文。

## 4. “最合适”的优化建议（优先级）

### P0（先做，收益最高）

1. **统一调度主干，消除双轨执行**
   - 现在存在“本仓 `*_evolution_runner.py`”与“外部 `optimize_*` 脚本”并行。
   - 建议选一条主链作为生产路径，另一条降级为备份/实验，避免状态漂移和重复建单。

2. **补齐“规划者统一派发”链路**
   - 增加 coordinator 定时消费任务队列（基于 `next-todo`）并统一分配。
   - 保留直派能力仅用于紧急或 bypass 场景，让主流程可追踪更清晰。

3. **正式启用钉钉日报任务并做验收**
   - 确认 `ops_daily_work_report_dingtalk` 已安装并启用。
   - 用 1-2 天观测“去重是否准确、异常是否漏报”。

### P1（第二阶段，提升“进化质量”）

4. **新增“全量校准窗口”而非全量常开**
   - 保持增量为主，增加周/双周全量校准（对话+memory+治理规则），输出偏差报告并自动修补状态索引。
   - 这样能兼顾成本与完整性。

5. **扩展互联网来源并做可信度评分**
   - 在 GitHub 之外加官方文档/精选技术源（白名单）。
   - 引入来源可信度与落地价值评分，降低噪声建议。

6. **统一群聊输出模板**
   - 统一字段：阶段、负责人、状态、风险、下一步、证据路径。
   - 让所有 runner 输出一致，减少人工理解成本。

### P2（第三阶段，治理增强）

7. **复杂度评分标准化入库**
   - 在 task_center 增加复杂度字段与计算来源，和风险/token/耗时并列。
   - 后续可用于更精细的路由与积分策略。

8. **做统一“运营看板”汇总脚本**
   - 聚合任务流转、失败重试、升级人工、token 成本、agent 积分、路由命中率。
   - 每日自动产出一份“决策视图”。

## 2026-03-06 上游迁移补充

围绕 OpenClaw 官方上游接入，本轮额外收敛了 4 个边界：

1. Cron 仍保留本地业务任务定义，但运行时 surface 统一回到官方 `openclaw cron`。
2. Hooks 改为官方 loader 管理，本仓库只保留 hook 逻辑与说明文档。
3. Python 治理层继续独立存在，但只通过官方 `cron/hooks/webhook` 入口触发。
4. Telegram channel、telegram plugin 与仓库 skills 目录统一回到官方配置 surface。

这意味着：

- 本仓库的价值继续集中在治理逻辑和业务 overlay。
- 官方运行时职责与本地治理职责已经可以分层升级。
- 后续升级 `vendor/openclaw-official` 时，不需要再同步回填本地治理逻辑。
