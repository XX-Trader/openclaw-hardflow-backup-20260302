# 运维进程监控说明

## 目标

为 `ops-agent` 增加“按项目声明常驻进程/服务”的持续巡检能力。

- 知道服务器上有哪些项目需要长期运行。
- 知道每个项目应该运行哪些进程或 systemd service。
- 把这些目标的状态和关联日志并入现有 `ops_cron_runner.py` 巡检结果。
- 保留“随时停监控”的显式开关，不自动执行高风险停服动作。

## 新增配置

项目注册表 `scripts/openclaw-ops/policy/project-registry.example.json` 现在支持：

```json
{
  "runtime_monitoring": {
    "enabled": true,
    "items": [
      {
        "id": "project-a-api",
        "name": "project-a-api",
        "type": "process",
        "required": true,
        "match": "uvicorn app.main:app",
        "cwd": "/srv/project-a",
        "log_paths": ["logs/api.log"],
        "stop_command": "pkill -f 'uvicorn app.main:app'"
      },
      {
        "id": "project-a-worker",
        "name": "project-a-worker",
        "type": "service",
        "required": true,
        "service_unit": "project-a-worker.service",
        "log_paths": ["/var/log/project-a-worker.log"],
        "stop_command": "systemctl stop project-a-worker.service"
      }
    ]
  }
}
```

字段约定：

- `enabled`: 项目级监控开关。
- `items[]`: 该项目应长期运行的目标清单。
- `type`: 目前支持 `process` 和 `service`。
- `match`: `process` 类型使用 `pgrep -af` 做命令行匹配。
- `service_unit`: `service` 类型使用 systemd unit 名称检查。
- `required`: 为 `true` 时，未运行会被视为风险。
- `log_paths`: 这些日志会被并入 `ops_cron_runner.py` 的扫描列表。
- `stop_command`: 只作为运维提示信息输出，不会被巡检器自动执行。

## Runner 行为

`skills/library/control-plane-ops/scripts/ops_cron_runner.py` 新增 `runtime_monitor` 配置块：

- `enabled`
- `project_registry`
- `max_projects`
- `max_items_per_project`
- `process_timeout_seconds`
- `service_timeout_seconds`

巡检时会：

1. 读取项目注册表中的 `runtime_monitoring.items[]`。
2. 检查每个目标当前是否处于 `running`。
3. 把缺失项记入风险原因：`runtime_process_missing=<count>`。
4. 把监控异常记入风险原因：`runtime_monitor_error=<count>`。
5. 把 `log_paths` 追加到日志扫描集合。
6. 在巡检输出中直接列出缺失的项目、程序、类型、日志路径和 `stop_command` 提示。

## 如何停监控

有两种方式：

1. 停某个项目或某个程序的监控
   直接把注册表里的 `runtime_monitoring.enabled=false`，或把某个 `item.enabled=false`。

2. 暂停整套巡检任务
   使用现有命令：

```bash
python skills/library/control-plane-ops/scripts/cron_switch.py off --scope managed
```

恢复时：

```bash
python skills/library/control-plane-ops/scripts/cron_switch.py on --scope managed
```

## 当前边界

- 当前版本只做“监控、告警、日志关联、停监控开关”。
- 当前版本不会自动执行 `stop_command`，避免巡检任务误停服务。
- 如果后续需要“运维 agent 显式执行 start/stop/restart”，建议单独做一个人工确认入口，而不是塞进巡检任务。
