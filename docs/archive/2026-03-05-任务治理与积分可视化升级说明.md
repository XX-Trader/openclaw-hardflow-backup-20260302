# 2026-03-05 任务治理与积分可视化升级说明

## 目标
- 人类下发任务在执行前必须先确认，避免理解偏差。
- 任务全链路可追踪，明确 `task_id`。
- 任务报表可直接看到完成时间、耗时、Token（百万 M）与成本。
- 每个 Agent 的任务得分可见，并进入统一积分账本。

## 本次变更

### 1) 人类任务默认执行前确认
- 文件：`skills/library/control-plane-ops/scripts/policy/policy_enforcer.py`
- 规则：
  - `request_source=human` 时，`create-task` 默认 `need_human_confirm=true`。
  - `request_source=ai` 且低风险时，默认可直接执行。
  - 高风险任务仍按原策略要求确认。
- 执行门禁：
  - `pre-stage` 会拦截未确认任务，返回明确错误。

### 2) 任务跟踪增强（ID 与跟踪快照）
- 文件：`skills/library/control-plane-ops/scripts/policy/policy_enforcer.py`
- `route-task` 新增：
  - `task_id_suggested`
  - `execution_strategy`（执行模式、是否需确认、原因）
- `create-task` 新增返回：
  - `tracking`（task_id/status/pool/assignee/created_at 等）
  - `confirmation`（确认状态、原因、确认命令模板）

### 3) 完成时间、耗时、Token(M) 可见化
- 文件：`skills/library/control-plane-ops/scripts/policy/task_center.py`
- 新增任务字段：
  - `started_at`
  - `completed_at`
- 状态流转自动维护时间：
  - 首次进入 `running` 自动写入 `started_at`
  - 进入终态（`passed/failed/escalated/cancelled`）自动写入 `completed_at`
- `task-report` 新增：
  - `timing`（创建到完成耗时、执行耗时、分钟）
  - `token_usage.total_tokens_m`

### 4) 每个 Agent 的得分展示
- 文件：`skills/library/control-plane-ops/scripts/policy/task_center.py`
- `task-report` 新增：
  - `agent_points`（任务级积分记录、按 actor 汇总、top agent）
- `daily-summary` 新增：
  - `agent_points`（按 actor_type/actor_id 的总分、均分、解决数）
- `planner-summary` 增强：
  - `by_agent` 内新增 `score_points`
  - `by_agent` 内新增 `total_tokens_m`

### 4.1) 计分规则调整（2026-03-05 增补）
- 文件：`skills/library/control-plane-ops/scripts/policy/policy_enforcer.py`
- 规则：
  - `planner`：按分发任务计分（`assign-task` 时记分，分发越多，得分越高）。
  - 其他执行 Agent：按任务完成结果计分（`report-agent-result` 时记分）。
- 默认参数：
  - `planner_dispatch_points_by_priority`: low=1.0, medium=1.5, high=2.0
  - `planner_dispatch_risk_multiplier`: low=1.0, high=1.1

### 5) SOUL 中写入“高分驱动”
- 文件：`agents/*/SOUL.md`
- 为所有 Agent 追加 `## Score Mission` 段落：
  - 以高质量完成任务、低失败率、SLA 时效作为得分核心。
  - 禁止为刷分绕过澄清/确认/评审/测试门禁。

## 向后兼容
- 数据库字段通过 `ALTER TABLE` 自动补齐，兼容既有库。
- 旧命令参数不变，只在 JSON 返回中增加新字段，不破坏原调用。
