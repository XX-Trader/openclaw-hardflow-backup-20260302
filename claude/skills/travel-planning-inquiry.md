# travel-planning-inquiry - 旅游规划询问技能

## 功能描述

在进行旅游规划前，通过结构化询问收集用户的详细需求和偏好，确保生成的攻略精准贴合用户实际情况。

## 触发条件

当用户提出以下类型的请求时自动触发：
- "帮我做个攻略" / "制定出行计划"
- "从A到B怎么去"
- "推荐旅游景点/路线"
- "周末/假期去哪里玩"

## 核心原则

**重要**: 在生成攻略之前，必须先使用 `AskUserQuestion` 工具询问用户细节特点。不要假设或猜测用户偏好。

## 执行流程

### 步骤1: 复述需求
- 用自己的话准确复述用户的出行目标
- 确认起点、终点、大致时间

### 步骤2: 结构化询问
- 按阶段使用 `AskUserQuestion` 工具
- 每轮最多4个问题
- 等待用户回答后再进入下一阶段

### 步骤3: 确认细节
- 针对用户的回答进行澄清
- 特别注意：
  - "3点出发" vs "3点到达"
  - "北门" vs "南门" 的具体位置
  - 公交发车间隔、末班车时间

### 步骤4: 目标分解与阻力分析 ⭐核心流程

#### 4.1 指定主要计划
```
主要目标：{起点} → {目的地}，{时长}内完成{核心活动}
例：四海城 → 大夫山，2.5小时内完成爬山+划船
```

#### 4.2 时间轴分解（按时间段划分小目标）

将整体计划分解为若干个小目标，每个小目标包含：

| 小目标 | 时间窗口 | 完成标准 | 依赖关系 |
|--------|----------|----------|----------|
| G1: 两人到达桌球馆 | 13:00-13:30 | ✅ 开始打球 | 无 |
| G2: 打桌球1小时 | 13:30-14:30 | ✅ 结束付费 | G1 |
| G3: 到达大夫山北门 | 14:30-15:00 | ✅ 汇合成功 | G2 |
| G4: 爬山登顶 | 15:10-15:50 | ✅ 山顶拍照 | G3 |
| G5: 下山到湖边 | 15:50-16:10 | ✅ 到达码头 | G4 |
| G6: 划船1小时 | 16:10-17:10 | ✅ 还船 | G5 |
| G7: 离园 | 17:30-18:00 | ✅ 出园门 | G6 |

#### 4.3 阻力点分析（逐个小目标识别风险）

**阻力点分类矩阵**：

| 阻力类型 | 具体表现 | 影响目标 | 应对策略 |
|----------|----------|----------|----------|
| 👥 **人** | 体力不支/意见不合 | G4/G6 | 提前约定放弃点 |
| 🚗 **堵车** | 高峰期公交延误 | G3 | 预留20分钟缓冲 |
| 😤 **情绪** | 疲劳/不耐烦 | G5/G6 | 安排休息时间 |
| ⚠️ **意外** | 天气/设备故障 | 全部 | 准备备选方案 |

**详细阻力点清单**（以大夫山为例）：

```
G1 (前往桌球馆):
  👥 阻力: 一人迟到
     → 策略: 13:00准时发消息提醒

G2 (打桌球):
  😤 阻力: 打超时不愿停
     → 策略: 14:20提前提醒，14:30必须结束
  ⚠️ 阻力: 桌球馆人多排队
     → 策略: 提前电话预约

G3 (前往大夫山):
  🚗 阻力: 公交间隔15分钟等不到
     → 策略: 预留30分钟，备选打车
  👥 阻力: 第3人找不到汇合点
     → 策略: 发定位+实时位置共享

G4 (爬山登顶):
  👥 阻力: 体力差异大，有人不想爬
     → 策略: 半山腰作为放弃点，其他人继续
  😤 阻力: 爬到一半情绪低落
     → 策略: 约定"到山顶就奖励"

G5 (下山):
  👥 阻力: 膝盖不适
     → 策略: 改走缓坡或原路返回
  ⚠️ 阻力: 天黑/下雨
     → 策略: 16:00前必须开始下山

G6 (划船):
  🚗 阻力: 租船排队
     → 策略: 16:00到达码头，先排队
  ⚠️ 阻力: 天气突变
     → 策略: 看云层/风向判断

G7 (离园):
  🚗 阻力: 错过末班车
     → 策略: 17:30就开始准备
```

#### 4.4 优化路径识别

分析是否有更优的执行顺序：

**当前路径**：
```
桌球(1.5h) → 爬山(0.7h) → 划船(1h) = 总共3.2h
```

**优化路径A**（时间更紧时）：
```
桌球(1h) → 划船(1.5h) → 爬山(0.5h，只到半山)
```
✅ 优点：划船更放松，爬山可灵活缩短
❌ 缺点：爬山后疲劳无法通过划船缓解

**优化路径B**（体力一般时）：
```
桌球(1h) → 只划船(2h) → 放弃爬山
```
✅ 优点：轻松休闲，时间充裕
❌ 缺点：体验不到登顶风景

**路径决策矩阵**：

| 方案 | 时间控制 | 体力消耗 | 风险等级 | 推荐场景 |
|------|----------|----------|----------|----------|
| 原方案 | ⚠️ 紧 | ⚠️ 高 | 中 | 体力好、天气好 |
| 优化A | ✅ 宽松 | ✅ 中 | 低 | 时间不确定 |
| 优化B | ✅ 宽松 | ✅ 低 | 低 | 体力一般/天气热 |

### 步骤5: 规划方案
- 根据分析结果制定详细方案
- 包含：
  - 时间轴（精确到10分钟）
  - 交通路线（换乘、步行、发车间隔）
  - 活动顺序
  - 费用预算
  - **阻力点应对措施**
  - **备选方案**

### 步骤6: 输出可视化
- 生成 HTML 攻略文件
- 包含时间表、路线图、费用明细、阻力点分析
- 使用 `amap-visualize` 技能添加地图

## 常见问题处理

### 分批出发的关键询问
```
❌ 错误理解：3个人都从四海城出发，3点出发
✅ 正确认定：2人13:00出发打桌球，1人15:00直接到目的地汇合
```

**追问示例**：
- "第3个人是3点从四海城出发，还是3点就能到达目的地？"
- "汇合地点是在北门公交站还是景区入口？"

### 时间分配的关键询问
```
❌ 错误假设：有足够时间玩所有项目
✅ 正确认定：公园18:00闭园，实际游玩时间只有X小时
```

**追问示例**：
- "到达目的地是X点，公园Y点闭园，实际可用时间只有Z小时"
- "是否需要控制爬山/划船的时间？"

### 路线细节的关键询问
```
❌ 错误模糊：爬山、划船
✅ 正确认定：爬大乌岗226米顶峰，石阶路约40分钟；聚秀湖划四人脚踏船1小时
```

**追问示例**：
- "爬山想爬到山顶还是半山腰？"
- "划船想玩多久？30分钟体验还是1小时慢慢玩？"

## 输出规范

### Markdown 攻略文件
```
{日期}_攻略_{起点}到{目的地}_{人数}人出行_{特点}.md
```

### HTML 可视化文件
```
mcp/output/{日期}_{目的地英文}_trip_plan.html
```

### 必包含内容
1. **时间轴总览**：表格形式，每行标注时间和活动
2. **交通路线**：详细到"地铁几号线、几站、几分钟、票价"
3. **活动详情**：爬山路线、船型选择、费用对比
4. **费用预算**：分项列出 + 总计 + 人均
5. **重要提醒**：时间控制、安全提示、应急预案

## 注意事项

1. **不要猜测用户偏好** - 有不确定就问
2. **一次只问一轮** - 等回答后再问下一轮
3. **标注不确定点** - 在规划时列出需要现场确认的内容
4. **给出备选方案** - 至少提供2个方案供用户选择
5. **时间留有余量** - 交通、活动都要预留缓冲时间

## 实战案例

### 案例：四海城 → 大夫山 3人出行

#### 询问过程

1. **第一阶段**：确认分批出发（2人13:00打桌球，1人15:00到达）
2. **第二阶段**：确认爬山+划船都要体验，体力一般
3. **第三阶段**：确认地铁+公交方式
4. **追问细节**：汇合时间15:00，不走回头路下山

#### 目标分解

```
主要目标：四海城 → 大夫山，2.5小时内完成爬山+划船
```

| 小目标 | 时间窗口 | 完成标准 | 依赖 |
|--------|----------|----------|------|
| G1 | 13:00-13:30 | 到达桌球馆开始打球 | - |
| G2 | 13:30-14:30 | 打完桌球，结账离开 | G1 |
| G3 | 14:30-15:00 | 到达大夫山北门 | G2 |
| G4 | 15:10-15:50 | 登顶拍照打卡 | G3 |
| G5 | 15:50-16:10 | 下山到达聚秀湖 | G4 |
| G6 | 16:10-17:10 | 划船结束还船 | G5 |
| G7 | 17:30-18:00 | 离园回家 | G6 |

#### 阻力点分析

| 小目标 | 阻力类型 | 具体风险 | 应对策略 |
|--------|----------|----------|----------|
| G2 | 😤 情绪 | 打桌球超时不肯停 | 14:20提前提醒 |
| G3 | 🚗 堵车 | 公交间隔15分钟 | 预留30分钟缓冲 |
| G3 | 👥 人 | 第3人找不到汇合点 | 发定位+实时共享 |
| G4 | 👥 人 | 体力不支不想爬 | 半山腰作为放弃点 |
| G4 | 😤 情绪 | 爬到一半情绪低落 | 约定山顶奖励 |
| G5 | 👥 人 | 膝盖不适 | 改走缓坡 |
| G6 | 🚗 堵车 | 租船排队 | 16:00先去排队 |
| G6 | ⚠️ 意外 | 天气突变 | 看云层判断 |

#### 优化路径

**原方案风险**：时间紧张（2.5小时完成2个项目），体力消耗大

**优化方案A**（体力一般时）：
```
桌球(1h) → 划船(1.5h) → 爬山(0.5h，只到半山)
```

**优化方案B**（休闲为主）：
```
桌球(1h) → 只划船(2h) → 放弃爬山
```

#### 最终规划结果

| 时间 | 活动 | 备注 |
|------|------|------|
| 13:00 | 两人出发 | 前往桌球馆 |
| 13:30-14:30 | 打桌球 | ⚠️ 14:20提醒准备结束 |
| 14:30 | 前往大夫山 | 地铁+公交 |
| 15:00 | 三人汇合 | 北门公交站 |
| 15:10-15:50 | 爬山登顶 | 半山腰可放弃 |
| 16:10-17:10 | 划船 | 16:00先去排队 |
| 17:30 | 准备离园 | 不要逗留 |

**关键控制点**：
- ⏰ 14:20 必须提醒结束桌球
- ⏰ 15:00 汇合成功后开始计时
- ⏰ 16:00 到达码头排队租船

**备选方案**：如果16:00还没到湖边，直接放弃划船

## 快速参考：阻力点检查清单

在制定任何旅游计划时，逐项检查：

### 👥 人
- [ ] 体力差异是否考虑？有放弃点吗？
- [ ] 意见不一致如何决策？
- [ ] 有人迟到/早退的预案？

### 🚗 堵车
- [ ] 高峰时段是否避开？
- [ ] 公交/地铁间隔是多少？
- [ ] 有没有备选交通方式？

### 😤 情绪
- [ ] 时间太长会不会累？
- [ ] 等待时间有没有安排？
- [ ] 有没有休息/奖励点？

### ⚠️ 意外
- [ ] 天气突变怎么办？
- [ ] 设备故障（租不到船）怎么办？
- [ ] 末班车时间确认了吗？
