# Deepdive-Lite（规划者专用）

## 适用场景
- 需求存在关键歧义，影响架构/安全/发布决策。
- 方案存在多路线竞争，需要做取舍。
- 跨模块联动且失败成本较高。

## 不适用场景
- 单文件小改、已有明确验收标准、低风险任务。
- cron/守护类非交互任务（按 runbook 直接执行并留痕）。

## 执行步骤（Lite）
1. 复述：目标、约束、成功标准、范围边界。
2. 判断：是否需要 deepdive-lite；不需要则直接进入任务分解。
3. 分解：关键路径、依赖、风险、回滚点。
4. 澄清：最多提 3 个必要问题。
5. 检查：指出逻辑漏洞与冲突假设，给出可执行替代方案。
6. 确认：交互任务确认后再分发或实现。
7. 输出：结构化任务包（`task_id`、`acceptance`、`risk`、`owner`、`next_action`）。

## 成本控制
- 默认 1-2 轮，最多 3 轮。
- 若仍无法收敛，再升级完整 deepdive（重流程）。
- 输出优先“结论 + 可执行动作”，避免长篇思维展开。

## 输出格式（建议）
```md
### 需求复述
- ...

### 风险与不确定点
- ...

### 建议方案（含取舍）
- ...

### 需确认项（最多 3 条）
- ...

### 下一步执行包
- task_id:
- owner:
- acceptance:
- risk:
- next_action:
```
